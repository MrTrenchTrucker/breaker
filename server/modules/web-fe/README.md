# web-fe — README

The Breaker website, served from its own container on the VPN. Built today: the sign-in page and its scripts with the AES-GCM layer; the first-login key bootstrap (`js/bootstrap-crypto.js`, `js/bootstrap-net.js`); the registration modules (`js/register.js`, `js/register-net.js`, `js/register-policy.js`, `js/register-view.js`); the transcriptions modules (`js/transcriptions.js`, `js/transcriptions-net.js`, `js/transcriptions-view.js`); and the admin panel clients (`js/admin-*.js`). Measured 2026-11-18: 39 `.js` files under `src/main/resources/web/js/` and 54 `.mjs` files under `src/test/js/`. Users register and log in, and view, search and copy their transcriptions from any device. Decryption happens in the browser, not on the server. It also hosts the APK for download (no CA certificate to download) and gives admins a panel for users, the transcription service and agent tokens. Breaker serves plain HTTP; TLS is the admin's choice through any reverse proxy (ADR-034).

The sign-in hand-off page is built and enabled: `js/signin-crypto.js:4` is `export const available = true;`, the guard `crypto.available !== true` at `js/signin-page.js:112` is unchanged, and `src/test/js/signin-e2e.test.mjs:260` runs the whole flow through the real page with the real crypto. The first-login key bootstrap is built and wired into the page (`js/signin-page.js:95-96`; `js/bootstrap-net.js:67` posts `POST /v1/auth/keys`). The pending-sealed conversion is built and wired into the page (`js/signin-page.js:74-84`, opening function `js/unseal.js`).

Built now: an AES-GCM layer for the page (wrap and unwrap the data key, seal and open records) on vendored
@noble/ciphers 2.4.0, imported by `js/signin.js`; with `available` true the form is enabled. Also built, with no page around them yet: the device list (`js/devices*.js`), the admin status banner (`js/status-*.js`), the registration modules and the transcriptions modules.

Full module card, including how to run its tests: `AGENTS.md` in this folder.
