# deploy — README

Thirteen scripts are built (`scripts/health-check.sh`, `scripts/release-tags.sh`, `scripts/backup-data.py`, `scripts/vpn-bind.sh`, `scripts/git-pull.sh`, `scripts/install.sh`, `scripts/update.sh`, `scripts/rollback.sh`, and the release pipeline `scripts/build-apk.sh`, `scripts/sign-apk.sh`, `scripts/sign-manifest.sh`, `scripts/write-manifest.sh`, `scripts/serve-release.sh`) with their shared helpers `scripts/deploy-common.sh` and the schema-record helper, and tests; the three image recipes, the one compose file, the env example and the secrets gate are built; the release pipeline scripts are tested with stubs for docker and have not been run against a real Gradle or `apksigner` build; any key-generating script, the key rotation and the app wiring that pins the manifest key are not built, and the paragraph below is the target design.

Wires Breaker's own containers (whisper-server, sync-api, web-fe, training) onto the self-hosted server securely, and ships updates. It covers binding to the VPN interface only, plain HTTP on Local Server, API keys kept out of git, APK signing, and a git-pull deploy of tagged releases with rollback. No certificate handling in Breaker; TLS is the admin's choice through any reverse proxy (ADR-034). Built and tested (approved 2026-11-18, ADR-043; not run on a real server): the install script prints the first-admin install code once, at the end of install, only to a terminal with shell tracing off.

Full module card, including how to run its tests: `AGENTS.md` in this folder.
