# auth-client — README

Handles registering and logging in, and keeps the user's token in a file sealed under an Android Keystore key (the vault is built in the app). That token authenticates sync, training and transcription calls. The password never leaves the phone: the module sends only a value derived from it (see ADR-006). Password changes and completing an admin reset are planned, not built here. A session the server issues expires 30 days after its last use (ADR-031); the client keeps no clock for it and learns that a session is over when the server refuses the key. When the phone has no live session, Home shows a quiet notice with a way to sign in (ADR-033, planned, not built).

Built today: the wire codec (the strict JSON reader, the request encoder for register, salt and login, the response decoder for those three answers, the KDF guard) and the groundwork for the calls: the HTTP port, the fixed-text failures, the account rules with the username check, the session vault port, the session record (it keeps the server address the session was made with) and a function that says whether two server addresses are the same server. Also built: the server auth service, which registers, logs in, signs out and returns the stored session over the HTTP port, wipes the password array after use, and uses a stored session only at the address it was made with. One call returns the stored session together with the address read now, or nothing when the two are not the same server, so a caller never pairs a session with an address read at another moment. After the login reply, a new sign-in revokes the session the vault holds, at that session's own server, and then stores the new one. The password change and the reset completion above are planned, not built.

Built (ADR-035, ADR-036): signing in on the Breaker website hands the login to the app. The app makes a one-time secret and a key pair for that sign-in. `HandoffFinish` trades the returned code and the secret for a session and a sealed key package, opens the package with the key pair, stores the keys and then the session, and wipes the attempt on every path. If a step fails after the server issued a session, both stores are cleared and that one session is revoked once, best effort. It does not revoke a session the phone already holds. Sign-out ends this device only.

Built outside this module (core, crypto, ui, app): the start of that sign-in: the one-time secret and key pair, the link to the website, the return link `breaker://handoff`, the start screen, the return activity and the Keystore-sealed file that holds the keys.

logout has no reply body to map; `ServerAuthService.logout()` is built and always clears the vault.
Full module card, including how to run its tests: `AGENTS.md` in this folder.
