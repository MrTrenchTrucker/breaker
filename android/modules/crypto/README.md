# crypto — README

Encryption by default, done on the phone. Built: it turns the user's password into a key-encryption key and a login value (key derivation), unwraps the user's data key with a key-encryption key, encrypts and decrypts transcriptions with AES-256-GCM and associated data, makes the one-time sign-in secret and key pair in memory, and opens the sign-in package with its private key (the sealed-box open). Not built: generating the data key or the account's box key pair, wrapping a new data key, and unsealing results an agent's job sealed to the user. The password, the key-encryption key and the plain data key never leave the device (ADR-006, ADR-018). The sign-in secret and key pair live in memory only: no Keystore, no file, no settings, no log. A Kotlin String cannot be wiped, so the secret text exists as a String only while it is built; the exchange request makes its String at the moment of the call and nowhere else. After a website sign-in the app keeps the plain keys in memory only while in use and, at rest, only as Keystore-sealed blobs in its own file; logout removes them. That store is the app's work, not this module's.

Full module card, including how to run its tests: `AGENTS.md` in this folder.
