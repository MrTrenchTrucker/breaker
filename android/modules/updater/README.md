# updater — README

The due decision, the version order, the digest check, the update decision, the check itself (asking the server for the latest release and saying whether it is newer), the download of the APK (only from the configured server, verified by its SHA-256 before it lands), the signature check (an Ed25519 signature over the version and the digest, against pinned keys), the verify step that joins the download and the signature check, the daily rule, the install step through the system installer port, the daily timer and the update checker with its one builder are built, with tests. The app wires them in: the installer adapter, the owner's key list and the timer start. Built, not tried on a phone: nothing here has run on a phone, so the install dialog, a cancelled dialog, a failed install and a re-offered older build are NOT VERIFIED on a device.

Keeps Breaker up to date. Once a day it checks the project's own server for a newer release, and an admin can force a check. It installs only APKs whose signature and SHA-256 check out. A bad release is undone by a server re-offer of an older build under a higher version code, which the phone takes as an ordinary update (decided 2026-11-18: the phone has no undo action of its own). It replaces the base app's updater, which was removed because it pointed elsewhere.

Full module card, including how to run its tests: `AGENTS.md` in this folder.
