# AGENTS.md - android/app/

## Purpose
Android entry point, dependency injection wiring, Gradle build.

The app also composes the dictation parts that exist on main and runs the armed microphone service (ADR-022 as amended); where a part is not merged the app passes an implementation that says so (a failure result), never a success.

The app also shows the floating tile while the microphone service is on and drives it from its taps, composes the on-device speech engine, with its real recognizer, over a model store, offers one button that downloads the speech model, and remembers a switch-off the user chose; opening the app from its launcher icon switches dictation on again.

**Build phase:** Phase 1. Needs first: `core` (on `main`); it wires each other module in as that module lands. This card covers the app as it stands: it wires `settings`, `ui`, `history`, `audio`, `format`, `transport`, `overlay`, `stt-ondevice`, `ui-tokens` and `model-registry`, and its launcher activity hosts a download button, the walk-through, a download state line, a History button and then the settings screen.

## Public Interface
app-level composition of all modules. Concretely, the app's own types are:
- `BreakerApp` - the `Application`; builds and holds the composition root, the microphone service controller (`dictationServiceController`) and the text committer (`textCommitter`, made once per process from the application context by `appTextCommitter`), and schedules the start-up purge on the scope `createPurgeScope` returns. It also builds, on first use, the `armedSwitch` (an `ArmedSwitch` over the controller and the file `dictation-off` in the files directory) and the `tileHost`; `onCreate` sets the controller's one state observer after the purge call, and the observer tells the switch first and then the tile host. It also builds `realMicSource` lazily from the application context's `AudioManager` and passes it to the composition root as `micSource = realMicSource`.
- `BreakerCompositionRoot` - the single place modules are composed; takes a files directory (plain JVM, testable without Android), the history store (as a value, or as a supplier that is called on first use) and the service controller and the committer, and exposes the `SettingsStore`, the credential-reference `Keystore`, the `HistoryStore` and the `dictation` component (built on first use). It also exposes the `modelStore` (a `LocalModelStore` over `models` in the files directory). The local engine of the `dictation` component is `OnDeviceSttEngine` over a `ModelLoader` on that store, with the real recognizer factory (`SherpaOnnxRecognizerFactory`, built with no argument, so with the thread count the module chooses, and held by the swap point `RECOGNIZER_FACTORY`); the text committer is the required `committer` parameter, which the app makes with `appTextCommitter` in `wiring/AndroidSwaps.kt` (the android half of the swap point; once per process, from the application context), and the microphone comes from the swap point in `Swaps.kt` (the microphone is also the default of the `micSource` parameter, `appMicSource()`). The supplier constructor gains a trailing optional `micSource` parameter forwarded by name; the three-argument constructor is unchanged.
- `SettingsLauncherActivity` - the launcher activity; hosts a column with the app's own button "Download the speech model" (it calls `TileHost.requestDownload`), then the walk-through the `ui` module builds, then a line that shows the download state, then a History button, then the settings view the `ui` module builds. While visible it registers itself as the download listener (`onResume`) and clears it (`onPause`), so a closed screen is never held. Each time it becomes visible, `onStart` reads the intent that started the activity: when `isIconLaunch` says the launcher icon started it, it calls `armedSwitch.switchOn()`, which switches the microphone service on also after a switch-off of the user; for any other start it calls `armedSwitch.armAtStart()`, which switches the service on only when no switch-off of the user is stored. Then it calls `tileHost.onLauncherVisible()`. A launch that carries the route extra `ROUTE_MODEL` ("model", read in `onCreate`) puts the button in focus, also in touch mode. A tap on the History button, or a launch that carries the route extra `ROUTE_HISTORY` on a fresh create (read in `onCreate` only when `savedInstanceState` is null, through `NotificationRoute.opensHistory`), shows the history screen the `ui` module builds, with the app's one history store, in place of the settings column: the content view is swapped in the same activity.
- `FileCredentialRefHolder` - a `Keystore` implementation backed by a file, holding the credential *reference* (never a secret).
- `SystemClockAdapter` - the app's `Clock` adapter (the real system clock; plain JVM).
- `AppStartPurge` - schedules the one start-up purge on the scope it is given (the app gives it the I/O-dispatcher scope of `PurgeScope`), off the main thread, reporting a failure to a callback instead of letting it escape.
- The composition root exposes the `HistoryStore` as a `LazyHistoryStore` over the supplier it is handed (the concrete `SqliteHistoryStore` the app builds, opened on first use); a store handed in as a value is exposed as it is.
- `PurgeScope` - `createPurgeScope()`: the app-lifetime scope on the I/O dispatcher with a supervisor job, for the start-up purge.
- Service package `dev.breaker.dictation.service` (plain Kotlin, tested on the JVM; the microphone service of ADR-022 as amended is armed while the app is visible or by its notification action, and the tile tap only begins capture inside the running service):
  - `DictationServiceController` - the one answer to "is the microphone service on" and its start and stop: `arm()` (the app is visible), `coldStart()` (the tile was tapped while it was off; one try, a refusal gives "Open Breaker once to switch dictation on."), `adopt()` (the service marks itself on when started from its notification), `disarm(reason)` (halts once and tells the observer the reason), `serviceEnded()` (marks off without halting, then calls the listener), `setEndedListener(listener)` (tells the owner the service ended), `setStateObserver(observer)` (one slot, a second call replaces the first; called only when the switch really changes: with `true` and no reason for `arm`, `coldStart` and `adopt`, with `false` and the `DisarmReason` for `disarm`, with `false` and no reason for `serviceEnded`; an observer that throws is swallowed), and `isArmed`. It never throws.
  - `DisarmReason` - `USER_WORD` or `OWNER_CLOSED`; `StartResult` - `Started`, `AlreadyRunning` or `NotStarted(sentence)`; `MicPermission` - whether RECORD_AUDIO is granted; `ServiceLauncher` (with `LaunchResult`) - starts and halts the real service.
  - `ServiceAction` with `ACTION_ARM`, `ACTION_DISARM` and `serviceActionOf` - the exact-match reading of a start request's action; `ServiceStartDecisions` (with `StartDecision`) - the pure rule for what the service does with each request.
  - `ServiceStartHandler` and `ServiceHost` - what the service does with each start request; the first call is always the foreground, then the request is read. `ServiceHost` holds the three platform calls.
  - `ReportingMicSource` - wraps the microphone source and reports once when a take ends by itself; it releases a failed device itself, and stays silent after `markStopRequested`; `rearm` starts the next take.
  - `NotificationRoute` - the names of the route a tap on the ongoing notification carries (`EXTRA_ROUTE`, `ROUTE_HISTORY`, and `ROUTE_MODEL` with the value "model" for the missing-model notification) and the launcher activity it opens (`TARGET_ACTIVITY`); the launcher honours `ROUTE_HISTORY` through `opensHistory(route)`.
  - `ServiceSentences` - the plain sentences the controller answers with.
- Android adapters in the service package (thin, one platform call per member, checked by text gates): `DictationForegroundService` (the microphone foreground service), `AndroidServiceLauncher`, `AndroidMicPermission`, and `DictationNotification` (module-internal; the quiet ongoing notification with one "Switch off" action; its title, its action label and its plain content line are in `strings.xml`; `build` is the plain one, and `withText(context, text)` builds the same notification with the given content line, which carries the taken line, a Kotlin constant and not a string resource).
- `ModelNotifications` in the service package (module-internal; a channel of its own, `speech-model`, that makes no sound): four notices, namely the speech model is missing, the model is downloading (an endless progress bar), the download is done or has failed, and the tile could not be shown. Each tap is one immutable `PendingIntent.getActivity` to the launcher with a request code of its own. The words are Kotlin constants, in plain words for the user; with notifications switched off nothing shows.
- Host package `dev.breaker.dictation.host` (the Android classes that join the wiring to the platform; checked by text gates):
  - `AppThreads.kt` - `MainLooperPost` (runs a block on the main looper, always queued, never inline) and `SerialBackground` (blocks one at a time, in order, on one named daemon thread; a block that throws is dropped and the next still runs). It is the only file in the app that names a handler, a looper, an executor or a thread.
  - `OverlayTilePort` - the `TilePort` over the overlay module's `FloatingTile`; built on the first show; maps the show result to `TileShow`.
  - `TakenClipboardAndroid` - the `TakenClipboard` over the phone's primary clip, labelled with the app's name; main thread only.
  - `TileHost` - builds the tile coordinator and the model downloader over the one model store. `onArmedChanged(armed)` (any thread) starts or stops the gesture and shows or hides the tile, `onLauncherVisible()` shows the tile again while the switch is on, `requestDownload()` is the download entry point, `setDownloadListener(listener)` sets the in-app download listener (the activity sets it while visible and clears it), and `openLauncher(route)` makes it the `Opener` of the tile. Its `init` hands `onTakeEnded` and `onMicTaken` from the composition root to the coordinator through the main post. The taken line reaches the notification through `setNotificationLine`: `DictationNotification.withText` for a line, and the plain `build` when the line is cleared. The coordinator's clipboard seam is `appTakenClipboard(context)`, and its history is the app's history store.
- Wiring package `dev.breaker.dictation.wiring`:
  - `DictationComponent` - builds the capture, the two core use cases and the runner from their ports; `close()` drops the dictation, switches the service off and is idempotent; `bindTo(scope)` closes it when the scope ends.
  - `DictationRunner` - drives one dictation at a time: `begin()` (`BeginResult`, whose `Taken` answer means another app or a call holds the microphone), `finish()` (`FinishResult`), `send()`, `cancel()`, `onCaptureEnded()`, `onServiceEnded()`, `resetAfterTaken()` (a taken take back to idle, with no second audio stop), `disarm()`. It stops capture, never the service, except `disarm()`. `RunnerSentences` holds its plain sentences.
  - `LazyHistoryStore` - a `HistoryStore` that builds the real one on first use; a supplier that throws is not remembered.
  - `UnavailableSttEngine` (now the server engine slot only), `UnavailableMicSource` - the honest-failure slots for the server engine and the microphone that are not merged (with `SERVER_UNAVAILABLE_DETAIL`, `MIC_UNAVAILABLE_MESSAGE`); each answers with a failure, never a success. The on-device engine is the real `OnDeviceSttEngine`, and the recognizer behind it is the real one, held by the swap point `RECOGNIZER_FACTORY`.
  - `UuidIdSource` - the `IdSource` over random UUIDs.
  - `TilePorts.kt` - the ports of the tile: `TileShow`, `TilePort`, `MainPost`, `Background`, `TakePort`, `ModelReady`, `ModelNotice`, `Opener`, and `ROUTE_MODEL_VALUE` ("model", equal to `NotificationRoute.ROUTE_MODEL`). `TakePort` also has `resetAfterTaken`, which `TakePortAdapter` passes to the runner.
  - `tileStateFor` - the one function that decides which state the tile shows; the busy face of a taken take (`micBusy`) comes after the off switch and before the sending, failed and sent states.
  - `TileCoordinator` - what each tap does and which state the tile shows: `onArmedChanged`, `onBegin`, `onCancel`, `onSend`, `onTap`, `onTakeEnded` (wired through `MainPost` when the mic ends by itself) and `onTakeMicTaken` (wired through `MainPost` by the tile host, for a take cut by the microphone); `onBegin` also needs the tile to be showing, so a failed or refused show means no begin. It is called on the main thread only; the take runs through `Background` and the answers come back through `MainPost`. `TakePortAdapter` presents the runner as a `TakePort`.
  - `TakeYield.kt` (`TakeYieldController`, internal): the taken branch of the coordinator, with the busy face flag, the lead line at the cut, the finish, reset and save on the background, and the copy and the settle line on the main thread (invariants 19 to 24). The settle always runs, even when the save to history fails.
  - `TakenClipboard.kt` - the one-method seam a taken take copies through (`copy(text)`), main thread only; the Android copy is `TakenClipboardAndroid` in the host package, built by `appTakenClipboard(context)`.
  - `TakenSentences.kt` - the pinned lines of a taken take (`LEAD`, `SAVED_AND_COPIED`, `TAKEN_NOTHING_HEARD`, `NOT_CONVERTED`, `COPIED_NOT_SAVED` and `STILL_TAKEN`), Kotlin constants, not string resources.
  - `NoopPorts.kt` - `GesturePort` with the placeholder `NoGesture`; the plain `appGesture()` in `Swaps.kt` keeps returning it.
  - `LaunchRule.kt` - `isIconLaunch(action, categories, route)`: true only for the start the launcher icon makes (the main action, the launcher category and no route); plain Kotlin that takes strings and names no Android type.
  - `ArmedSwitch` (with `SwitchOn`) - the one on and off switch over the controller: `isOn`, `switchOn`, `switchOff`, `armAtStart` and `onStateChanged` (the observer body). `OffStore` and `FileOffStore` - the user's switch-off kept as the presence of one file, written to a temporary file and renamed.
  - `ModelSupport.kt` - `ModelSentences`, `StoreModelReady`, `ModelInstallPort` (with `InstallerPort` and `modelInstallPortFor`, the adapter over the installer of the speech module), `InstallOutcome`, `ModelDownloadNotice`, `DownloadOutcome` and `ModelDownloader`, whose `requestDownload` is the one download entry point.
  - `Swaps.kt` - the swap points, in the table below (none of them names an Android type).
  - `AndroidSwaps.kt` - the android half of the swap points: the swaps that need an Android type live here, namely `appTextCommitter(context)` (the accessibility commit), `appMicSource(audioManager)` (the real microphone) and `appGesture(context)` with its `ShakeGesture` mapping (the real shake of the phone, read from the accelerometer), and `appTakenClipboard(context)` (the clipboard a taken take copies to, main thread). They are kept out of `Swaps.kt` so that file stays plain.

After a send the tile shows SENT until the next begin, cancel, tap or switch-off. A send whose text was committed, or only reached the clipboard, also shows SENT; a failed commit shows FAILED with its sentence. A tap or a gesture on a tile that shows SENT starts a take. The text itself is never given to the tile, and there is no timer. The app does not push SENT_LOCAL: no producer exists, because the server path is not built, and a server failure is surfaced, not retried on the phone.

## Invariants
app launches to a screen with the download button, the ui walk-through and a download state line above the settings view; DI wiring composes all modules.

1. The microphone service stops on a defined set of paths and no other. The user's off word, the notification's "Switch off" and the owner closing switch it off (`disarm`); the service ending on its own (a kill, a refusal inside the service) marks it off and drops the dictation under way. Capture stops on send, cancel, error and capture-ended, and the service stays on. A service started with nothing on, or with no valid switch-on action, stops at once. Tested by: `ServiceControllerTest`, `ServiceControllerOrderTest`, `ServiceStartDecisionTest`, `ServiceStartHandlerTest`, `DictationRunnerTest`, `DictationRunnerEndTest`, `DictationComponentTest`, `DictationComponentServiceTest`.
2. The foreground call is the first thing done on every start request, even one that is about to stop (the platform ends an app whose started foreground service never reaches the foreground). A refusal there ends the service quietly and marks the switch off; nothing is thrown out of the service. Tested by: `ServiceStartHandlerTest`, `ServiceShapeGateTest`, `ServiceAdapterGateTest`.
3. The app declares exactly the permissions INTERNET, RECORD_AUDIO, FOREGROUND_SERVICE, FOREGROUND_SERVICE_MICROPHONE, POST_NOTIFICATIONS and SYSTEM_ALERT_WINDOW (six), and the one private service of the microphone type with no intent filter. Clear-text traffic is off everywhere with no exceptions: the network configuration has one base config, trusts the system store only, and has no host entry, no override, no user certificate and no pinned key. The accessibility service entry comes from the commit module's library manifest and is not repeated here. Tested by: `ManifestGateTest`, `NetworkConfigGateTest`, `ServiceAdapterGateTest`, `AppCommitGateTest`.
4. A part that is not merged is passed as an implementation that answers with a failure, never a success: the server engine is the placeholder, and the microphone is real in the app (the placeholder stays only as the root default). The on-device engine with the recognizer behind it, and the text committer from the commit module (its accessibility commit), are the real parts. The server formatter slot holds the on-device rule-based formatter, and the server path is not reached while the server engine slot fails. Tested by: `UnavailableSlotsTest`, `DictationFlowTest`, `RootSlotsGateTest`, `RecognizerSwapGateTest`, `DictationComponentTest`, `DictationRunnerTest`, `SwapsTest`, `AppCommitGateTest`.
5. A microphone that fails is released by the app's own wrapper and then reported once; a stop the app asked for is never reported as an end by itself; the stop the capture thread cannot pay is owed and paid on the caller's thread by the next begin, cancel, disarm or service end. Tested by: `ReportingMicSourceTest`, `DictationRunnerEndTest`, `DictationComponentTest`.
6. The app asks for no permission at run time (onboarding does). The title, the action label and the plain content line of the ongoing notification are in `strings.xml`, and `ServiceSentences` holds the controller's sentences. The one exception is the taken line, which `withText` takes as its argument: it is a Kotlin constant (`TakenSentences`), and `NotificationTextGateTest` does not read it. The words of the model notices are Kotlin constants (`ModelSentences` and `ModelNotifications`), which `NotificationTextGateTest` does not read. The sentences for a failed download (`ModelSentences`), a ready model (`ModelNotifications`) and a missing microphone permission or a refused start (`ServiceSentences`) are pinned word for word. Tested by: `NotificationTextGateTest`, `PlatformNotificationGateTest` (the builder's facts: the quiet channel, the title, the action label and the content line from resources, the channel id as the only literal, and the ongoing flag), `ModelSupportTest`, `ServiceSentencesTest`, `HostGateNotifyTest`, `HostGateNoticeTest`; the no-run-time-request part is pinned by `NoPermissionRequestGateTest`.
7. The history database opens on its first use, which is the start-up purge, and that runs on the I/O thread, never on the main thread and never by reading the settings or the keystore. Tested by: `LazyHistoryStoreTest`, `LazyHistoryRootTest`, `AppWiringGateTest`.
8. The notification is quiet and ongoing, and a tap on it opens the launcher activity carrying the history route. The missing-model notification opens it with the route "model" and the tile-unavailable one with no route. Tested by: `NotificationContentGateTest`, `NotificationRouteTest`, `PlatformAdapterGateTest`, `HostGateNotifyTest`, `HostGateNoticeTest`.
9. The user's switch-off is kept in the file `dictation-off` in the app's files directory, written to a temporary file and renamed in one step. A switch-off the user chose (the notification's "Switch off", the off word, `ArmedSwitch.switchOff()`) stores it, also when the service was already off; every switch-on clears it; the service ending by itself and the owner closing never store it; and a start of the launcher that is not an icon launch switches the service on only when it is not stored (an icon launch switches it on whatever is stored: invariant 13). Tested by: `ArmedSwitchTest`, `OffStoreTest`, `ServiceControllerObserverTest`, `ArmedSwitchReasonTest`, `OffStoreThrowingFileTest`, `AppWiringGateTest`.
10. Every state the tile shows comes from `tileStateFor`. A tap on the tile's microphone with no ready speech model starts nothing, raises the missing-model notification and shows the same sentence beside the tile. A take sends once: a repeat before the tile shows sending is ignored; an empty take sends and commits nothing and shows the armed tile; a failed take shows its sentence; an answer that comes back after the switch went off is dropped; and a tile, notification or launcher call that throws never reaches the caller. A tile that cannot be shown gives a notification whose tap opens Breaker. Tested by: `TileStateMapTest`, `TileCoordinatorTest`, `TileCoordinatorTakeTest`, `TileCoordinatorMoreTest`, `TileEmptyTakeRealRunnerTest`, `TakePortAdapterTest`.
11. The tile coordinator is called on the main thread only and is reached only through the main post; the take runs on one serial worker (the download has its own), in submission order, and its answers come back through the main post; and only `host/AppThreads.kt` names a handler, a looper, an executor or a thread. Tested by: `HostGateTest`, `TileCoordinatorTakeTest`, `AppPrivacyScanTest`, `AppLayoutGateTest`.
12. The speech model has one download entry point, `ModelDownloader.requestDownload`. One download runs at a time (a second request answers `AlreadyRunning`); the address and the checksum come only from the registry entry for the id the settings select; progress is an endless bar, because none is known; a failed install leaves nothing the engine can read and the same call tries again; and a tap on the tile's microphone checks that the selected model is installed and unpacked (every file of the model's unpack profile, each not empty) before it begins. Tested by: `ModelDownloadEntryTest`, `ModelDownloaderDefaultLookupTest`, `ModelSupportTest`, `HostGateTest`, `HostGateNotifyTest`.
13. Opening the launcher activity from the launcher icon (the main action, the launcher category and no route) switches dictation on, also after a switch-off the user chose, and clears the stored switch-off; a start that carries a route or has no main action (a notification tap, the tile) never switches it on over a stored switch-off. Tested by: `LaunchRuleTest`, `ArmedSwitchTest`, `AppWiringGateTest`, `AppLayoutGateTest`. Whether the platform hands the icon's intent to the activity again on a return from recents or a rotation is not verified on a device (Known Gotchas).
14. The app packages the speech engine release file as a run-time dependency only (`runtimeOnly(sherpaCoordinate)`; the coordinate is built from the version catalog and the build file holds no version number of its own), the build tasks of the app depend on `verifySherpaAar` of the speech module, which checks the file against its pin, and only the `arm64-v8a` ABI is built. The swap point `RECOGNIZER_FACTORY` is the real factory built with no argument, and neither it nor the composition root names a placeholder recognizer. Tested by: `BuildFileGateTest`, `BuildFileSherpaGateTest`, `RecognizerSwapGateTest`, `RootSlotsGateTest`, `SwapsTest`, `DictationFlowTest`.
15. The app's microphone swap point returns the real microphone, not the unavailable placeholder. `appMicSource(audioManager: AudioManager): MicSource` returns `AndroidMicSource.create(audioManager)`, built once per process. The real microphone source is built lazily, on first use, not at app start. Tested by: `AppMicGateTest`.
16. When the microphone ends a take by itself, the tile coordinator's `onTakeEnded()` is called on the main thread through `MainPost`. A user stop or cancel does not fire it (`ReportingMicSource` stays silent after `markStopRequested`). A send in flight is not disturbed (`onTakeEnded` returns when `sendPushed`). Tested by: `DictationComponentTest`, `DictationFlowTest`, `HostGateTest`.
17. Microphone sharing (ADR-022): when the audio module reports that another app or a phone call has taken the microphone, the take is ended, not cancelled: what was captured is transcribed, saved to history and copied to the clipboard, never typed into the field, and the notification says that the recording stopped for a call or another app. A recording is never restarted on its own. Tested by: `TileCoordinatorTakenTest` (the saved text, the copy and the lead and outcome lines), `DictationComponentTakenHookTest` (the cut reaches the taken hook, not the device-failure end), `TakenSentencesTest` (the words).
18. A take begins only while the tile is on screen: the coordinator records whether the last attempt to show the tile succeeded, clears it when a show is refused or fails and when the switch goes off, and checks it before any begin from a tap or a shake, so with no tile on screen nothing begins. Tested by: `TileCoordinatorShownTest`.
19. A take cut by the microphone shows the busy face. The face is the tile state for a taken microphone: `tileStateFor` checks it after the off switch and before the sending, failed and sent states. The flag clears when a begin starts, when the switch goes off, and at the next take end; a take end clears the flag and the notice line, and the tile is redrawn at its next state change. The settle of a taken take keeps the face, so the armed tile is never shown while the microphone is held. Tested by: `TileStateMapTest` (the busy face wins over a pushed send, a failed take and a commit, and an off switch shows idle), `TileCoordinatorTakenTest` (the face is busy at the cut and after the settle; a begin after the settle clears it; a take end restores the plain line).
20. A tap or a shake on the busy face is a begin attempt through the same begin path as any other begin: it needs the switch on, the tile on screen, no begin already in flight and a ready speech model, and it does nothing while the taken branch is still running. A tap in any other state keeps its meaning. A begin refused as taken keeps the busy face and shows the refused line. A failed begin shows its failure and not the busy face. Tested by: `TileCoordinatorTakenTest` (a tap on the busy face reaches the begin and not the launcher; a take refused as taken shows the busy face and the refused line; a tap in idle opens the launcher and does not begin), `ShakeBeginPathTest` (a shake ends in the same begin as a tap).
21. A begin whose open is refused because another app or a call holds the microphone answers the taken result, not the failed sentence: the session stays idle with the service armed, and the tile shows the busy face with the refused line. A refusal from a broken device, and every other failure, keeps the failed answer. Tested by: `DictationRunnerTakenTest` (the taken answer and the idle session; the broken device answers failed), `TileCoordinatorTakenTest` (the refused take shows the busy face and the refused line).
22. The notification line follows the taken take: the lead line when the take is cut, then the line for its outcome when it settles (the text was saved and copied, the text was copied but the save to History failed, nothing was heard, or the speech could not be converted), the refused line when a tap is refused as taken, and the plain line again at the next state change. Every line is posted with the same notification id, so one notification shows at a time; it stays quiet, with the same channel, icon and tap that opens the history route. The taken lines are Kotlin constants in `TakenSentences`, not string resources. The copied-but-not-saved line is `COPIED_NOT_SAVED`, with the words "Recording stopped for a call or another app. Text copied, but not saved to History.", and it is posted when the text was copied and the history save threw. Tested by: `TileCoordinatorTakenTest` (the lines in order), `TakenSentencesTest` (the words and their lengths), `PlatformNotificationGateTest` (the content line is the one parameter of the builder and the channel is quiet), `NotificationTakenGateTest` (one builder, one content call and one `withText` signature), `NotificationContentGateTest` (the one history tap).
23. A take cut by the microphone saves its text to history on the background and copies it to the clipboard through the one-method `TakenClipboard` seam on the main thread. It never types the text into the field: the taken branch has no send and no committer. A take with no text saves nothing and copies nothing. If the save to history throws, the copy and the settle still run and the copied-not-saved line is posted. A take whose engine could not convert its audio shows the fixed conversion line, never the engine's own words. Tested by: `TileCoordinatorTakenTest` (the saved text and the copy; the blank and the empty take save and copy nothing; a thrown or failed conversion posts the fixed line and never the detail; a send during a taken transcription is refused and types nothing).
24. A take cut by the microphone stops the audio once, in the finish of the take. The reset that follows it (SENDING to IDLE, the pending text dropped) stops no audio, closes no device and leaves nothing to send. ## Swap Points
Where a part that is not built is swapped for the real one. Each is one declaration in `wiring/Swaps.kt`, or in `wiring/AndroidSwaps.kt` when it needs an Android type (the text committer, the android half of the swap point); the composition root and the tile host read them, and nothing else names a placeholder. `SwapsTest` pins what each answers today.

The engine library is a run-time dependency of the app, checked by `verifySherpaAar` before the app's build tasks |

## Test Requirement
Every test added or touched for this module must be proven to fail loudly:

applies to every tier and invariant listed above, not only the ones that seem
fragile.

## How This Module Is Built
One engineer owns this module and delivers it as one pull request, working on
one module at a time. The owner does not write the module's code. The owner:
- splits the work into sub-modules and has contributors write each one, code and
  tests;
- coordinates and orchestrates those contributors, checks every piece of their
  work, and sends back anything that is wrong until it is right;
- convenes a small panel of contributors to advise on design, risks and tests
  before and during the build;
- hands the finished, checked module directly to the maintainer as a single pull
  request.
The owner's own work is orchestration, checking and correction, not writing
code.

## Known Gotchas
- Phase 1 deliverable - DI wiring must be the ONLY place modules are composed.
- **NOT VERIFIED on a device or emulator.** What is checked for this scaffold is
  compile (`assembleDebug` plus the unit test) and the JVM tests of the
  composition root. The launcher activity and the real settings view are **not
  exercised** - the app has not been launched on a device or an emulator.
- **Start-up purge is one-shot and only logged.** `BreakerApp` schedules
  `SqliteHistoryStore.purgeExpired()` once on an app-lifetime coroutine scope
  on the I/O dispatcher (`createPurgeScope`), off the main thread. A failure is passed to a callback that logs it
  (`Log.w`); it is not retried and does not crash the app. Purge scheduling
  beyond app start is not built.
- The history database opens on first use, and the first use is the start-up purge, which runs on the I/O thread, never on the main thread.
- The history route arrives in `onCreate`, because the launcher intents (the notification, the model notice and the tile) carry `FLAG_ACTIVITY_NEW_TASK` and `FLAG_ACTIVITY_CLEAR_TOP`. The activity has no `onNewIntent` and the manifest declares no launch mode, so the recreate that delivers the route is expected, not proven; this path is not checked on a device.
- Back from the history screen is an `OnBackInvokedCallback` on API 33 and up, registered only while the history screen shows, and `onBackPressed` on API 30 to 32. The older `onBackPressed` override carries `@SuppressLint("GestureBackNavigation")` (only on that method) because lint flags the override; it closes the history screen whenever it shows on every SDK level and otherwise calls super, and Android 13 and newer Back goes through the callback registered while history shows, so closing must be safe to reach from either handler and happens once. Predictive back is not checked on a device.
- Back inside the 5 second undo window commits the pending delete at once, because leaving the history screen closes it; this is the `ui` screen's behaviour.
- The activity does not restore the history screen after a rotation. The history route is read only on a fresh create, so the settings column shows again.
- No test can run the activity. The gates read its source text, and `HostGateNotifyTest` pins the order of the launcher column, and `HistoryRouteGateTest` pins the history route and Back. Back is pinned by source text, not run. It needs a device check on the first test build on Android 13 to 15 and on Android 16: which handler fires, that the history screen closes exactly once, and that Back on the settings column leaves the app; an API 30 to 32 emulator too if one is at hand.
- Still to build: a small pure decision for Back (history showing and the SDK level give one of close, register, unregister or the default), with plain JVM tests. It is built after the first device build, or sooner if Back misbehaves.
- The History button is the app's own button. The `ui` settings screen has no History entry.
- `FileCredentialRefHolder` holds a credential *reference*, never a secret. The
  platform `Keystore` that would resolve the reference against a secret is **not
  built and not verified**; nothing in this module is a claim that a key is kept
  safe on the device.
- The walk-through is shown in the settings screen (under the Download button); ui decides what it shows. The app asks for no permission at run time (onboarding does).

A failed read is handled by `ReportingMicSource`, which releases the device and reports the end once; it relies on the source returning a negative value when it fails. A long run of empty reads is not seen: the stop stays owed until the next begin, cancel, disarm or service end. The future real microphone driver must return a negative code on failure, and its `close()` must be safe to call twice and from the capture thread.

After "Switch off", opening Breaker from its launcher icon switches dictation on again (it calls `ArmedSwitch.switchOn()`, the only caller); a start from a notification or the tile does not, so the stored switch-off blocks it (the switch row is the ui module's work).
