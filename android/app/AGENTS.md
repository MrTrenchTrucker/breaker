# AGENTS.md - android/app/

## Purpose
Android entry point, dependency injection wiring, Gradle build.

The app also composes the dictation parts that exist on main and runs the armed microphone service (ADR-022 as amended); where a part is not merged the app passes an implementation that says so (a failure result), never a success.

The app also shows a first-run view on a phone with no speech model, then the launcher, which opens on the home screen (see the first-run decision under Public Interface). The app also shows the floating tile while the microphone service is on and drives it from its taps, composes the on-device speech engine, with its real recognizer, over a model store, offers one button that downloads the speech model, and remembers a switch-off the user chose; an icon launch of the launcher activity switches dictation on once for each activity instance the icon created, and the on/off card on Home is a further route to the switch-on.

**Build phase:** Phase 1. Needs first: `core` (on `main`); it wires each other module in as that module lands. This card covers the app as it stands: it wires `settings`, `ui`, `history`, `audio`, `format`, `transport`, `overlay`, `stt-ondevice`, `ui-tokens` and `model-registry`, and its launcher activity opens on the Home screen (after the first-run view on a phone with no speech model); its Settings item opens the settings screen (with the speech model download, whose button calls `TileHost.requestDownload`).

## Public Interface
app-level composition of all modules. Concretely, the app's own types are:
- `BreakerApp` - the `Application`; builds and holds the composition root, the microphone service controller (`dictationServiceController`) and the text committer (`textCommitter`, made once per process from the application context by `appTextCommitter`), and schedules the start-up purge on the scope `createPurgeScope` returns. It also builds, on first use, the `armedSwitch` (an `ArmedSwitch` over the controller and the file `dictation-off` in the files directory) and the `tileHost`; `onCreate` sets the controller's one state observer after the purge call, and the observer tells the switch first and then the tile host. It also builds `realMicSource` lazily from the application context's `AudioManager` and passes it to the composition root as `micSource = realMicSource`.
- `BreakerCompositionRoot` - the single place modules are composed; takes a files directory (plain JVM, testable without Android), the history store (as a value, or as a supplier that is called on first use) and the service controller and the committer, and exposes the `SettingsStore`, the credential-reference `Keystore`, the `HistoryStore` and the `dictation` component (built on first use). It also exposes the `modelStore` (a `LocalModelStore` over `models` in the files directory). The local engine of the `dictation` component is `OnDeviceSttEngine` over a `ModelLoader` on that store, with the real recognizer factory (`SherpaOnnxRecognizerFactory`, built with no argument, so with the thread count the module chooses, and held by the swap point `RECOGNIZER_FACTORY`); the text committer is the required `committer` parameter, which the app makes with `appTextCommitter` in `wiring/AndroidSwaps.kt` (the android half of the swap point; once per process, from the application context), and the microphone defaults to the placeholder from the swap point in `Swaps.kt` (the default of the `micSource` parameter, `appMicSource()`); the app hands in the real one, made by `appMicSource(audioManager)` in `wiring/AndroidSwaps.kt`. The supplier constructor gains a trailing optional `micSource` parameter forwarded by name; the three-argument constructor is unchanged. It also holds the `levelSink` hook, a `LevelSink` that the tile host sets, and forwards it into the `dictation` component; the level source feeds both the tile mic and the screen mic on Home.
- `SettingsLauncherActivity` - the launcher activity; opens on the home screen the `ui` module builds (the on/off card with its switch, the big mic, the last transcript with a Copy button, and a menu with History, Settings, How it works and About), after the first-run view on a phone with no speech model. Settings opens the settings view the `ui` module builds, in a column that holds only that view. How it works and About open their own screens through `InfoScreensWiring` (`wiring/InfoScreensWiring.kt`), which takes the settings store, swaps the activity's content view and returns to Home on Back. The activity uses the framework no-title-bar theme (`@android:style/Theme.Material.Light.NoActionBar`), so the window draws no system title bar above the host's top bar. While visible it registers itself as the download listener (`onResume`) and clears it (`onPause`), so a closed screen is never held. `onResume` refreshes whichever screen is showing: the first run's view while it is up, the settings view while Settings is open, and Home otherwise. The download callbacks go through a `downloadControl()` helper that returns the first run's view while it is up and the settings view otherwise. A refusal from the icon launch is routed to Home's status line through `HomeControl.showLine`. Each time it becomes visible, `onStart` reads the intent that started the activity: when `isIconLaunch` says the launcher icon started it and the once-per-instance flag (`IconLaunchOnce`, saved in `onSaveInstanceState` and read back in `onCreate`) is not yet set, it calls `armedSwitch.switchOn()`, which switches the microphone service on also after a switch-off of the user; the flag is set only by an answer of On or AlreadyOn, so a refused start is tried again on the next start. Every other start calls `armedSwitch.armAtStart()`, which switches the service on only when no switch-off of the user is stored. Then it calls `tileHost.onLauncherVisible()`. The first-run decision runs first, in `onCreate`, after `settingsView` (a `lateinit` the download helpers read on every path) is set to a plain `View`, so the first-run path, which returns before Settings is built, never reads it unset (`SettingsViewSetBeforeFirstRunTest`): with no done marker and no model it shows the first-run view the `ui` module builds (`showFirstRun`) and returns before the home screen and the settings view are built; the view's `onFinished` writes the done marker and recreates the activity. With a ready model and no marker, the marker is written quietly. `progress` forwards each report to the shown view as `DownloadControl` (`downloadChecking` for the checking sentence, `downloadProgress` otherwise), so the first-run bar moves and the settings screen draws its own download line from it. The on/off card on Home is a second route to `switchOn()`, through `BreakerSwitchAdapter`. A launch that carries the route extra `ROUTE_MODEL` ("model", read in `onCreate`) asks for the settings view's download button to be in focus, also in touch mode; that button is in the settings view, which is not on screen while Home is the first screen shown, so by reading the call focuses nothing (a device check is owed). A tap on the History item of the Home menu, or a launch that carries the route extra `ROUTE_HISTORY` on a fresh create (read in `onCreate` only when `savedInstanceState` is null, through `NotificationRoute.opensHistory`), shows the history screen the `ui` module builds, with the app's one history store and the stored theme, in place of the screen it was opened from: the content view is swapped in the same activity, and closing it returns to Home, or to the settings view when Settings is open. When Settings is closed, Home and the settings view are built again, so they read the stored theme again.
- `FileCredentialRefHolder` - a `Keystore` implementation backed by a file, holding the credential *reference* (never a secret).
- `SystemClockAdapter` - the app's `Clock` adapter (the real system clock; plain JVM).
- `AppStartPurge` - schedules the one start-up purge on the scope it is given (the app gives it the I/O-dispatcher scope of `PurgeScope`), off the main thread, reporting a failure to a callback instead of letting it escape.
- The composition root exposes the `HistoryStore` as a `LazyHistoryStore` over the supplier it is handed (the concrete `SqliteHistoryStore` the app builds, opened on first use); a store handed in as a value is exposed as it is.
- `PurgeScope` - `createPurgeScope()`: the app-lifetime scope on the I/O dispatcher with a supervisor job, for the start-up purge.
- `PurgeGuard` - the start-up purge's pure clock-jump decision (`decide`): run now ([GO]) or skip and report skew ([DEFERRED_SKEW]). Automatic time on -> GO; automatic time off with no baseline yet (`PurgeBookkeepingStore.lastPurgeAt` unset) -> GO; off and at most 30 days (`GRACE_DAYS`) past the last purge -> GO; off and more than 30 days past it -> a forward jump is SUSPECTED, so skip and report skew for at most 7 days (`CAP_DAYS`) counted from the first skipped start, then purge as normal. `PurgeOutcome` (sealed) is the result: `Purged(report)` when it ran, `Skipped` when the guard deferred it for a suspected jump. `runGuardedStartPurge` reads the two bookkeeping instants, decides, runs the real `purgeExpired()` only under GO, records the instants, and returns the outcome; it is plain JVM.
- `AndroidAutomaticTimeOn` - the real `AutomaticTimeOn`: reads `Settings.Global.AUTO_TIME` over the resolver, default `1`. A resolver that cannot answer is read as automatic time on; the `automaticTimeFrom(read)` seam keeps the platform call at the boundary so the fail-safe (a read that throws is read as on, catching `Exception` never `Throwable`) is testable on a plain JVM.
- Service package `dev.breaker.dictation.service` (plain Kotlin, tested on the JVM; the microphone service of ADR-022 as amended is armed while the app is visible or by its notification action, and the tile tap only begins capture inside the running service):
  - `DictationServiceController` - the one answer to "is the microphone service on" and its start and stop: `arm()` (the app is visible), `coldStart()` (the tile or the Home big mic was tapped while it was off; one try, a refusal gives "Open Breaker once to switch dictation on."), `adopt()` (the service marks itself on when started from its notification), `disarm(reason)` (halts once and tells the observer the reason), `serviceEnded()` (marks off without halting, then calls the listener), `setEndedListener(listener)` (tells the owner the service ended), `setStateObserver(observer)` (one slot, a second call replaces the first; called only when the switch really changes: with `true` and no reason for `arm`, `coldStart` and `adopt`, with `false` and the `DisarmReason` for `disarm`, with `false` and no reason for `serviceEnded`; an observer that throws is swallowed), and `isArmed`. It never throws.
  - `DisarmReason` - `USER_WORD` or `OWNER_CLOSED`; `StartResult` - `Started`, `AlreadyRunning` or `NotStarted(sentence)`; `MicPermission` - whether RECORD_AUDIO is granted; `ServiceLauncher` (with `LaunchResult`) - starts and halts the real service.
  - `ServiceAction` with `ACTION_ARM`, `ACTION_DISARM` and `serviceActionOf` - the exact-match reading of a start request's action; `ServiceStartDecisions` (with `StartDecision`) - the pure rule for what the service does with each request.
  - `ServiceStartHandler` and `ServiceHost` - what the service does with each start request; the first call is always the foreground, then the request is read. `ServiceHost` holds the three platform calls.
  - `ReportingMicSource` - wraps the microphone source and reports once when a take ends by itself; it releases a failed device itself, and stays silent after `markStopRequested`; `rearm` starts the next take.
  - `NotificationRoute` - the names of the route a tap on the ongoing notification carries (`EXTRA_ROUTE`, `ROUTE_HISTORY`, and `ROUTE_MODEL` with the value "model" for the missing-model notification) and the launcher activity it opens (`TARGET_ACTIVITY`); the launcher honours `ROUTE_HISTORY` through `opensHistory(route)`.
  - `ServiceSentences` - the plain sentences the controller answers with.
- Android adapters in the service package (thin, one platform call per member, checked by text gates): `DictationForegroundService` (the microphone foreground service), `AndroidServiceLauncher`, `AndroidMicPermission`, and `DictationNotification` (module-internal; the quiet ongoing notification with one "Switch off" action; its title, its action label and its plain content line are in `strings.xml`; `build` is the plain one, and `withText(context, text)` builds the same notification with the given content line, which carries the taken line, a Kotlin constant and not a string resource).
- `ModelNotifications` in the service package (module-internal; a channel of its own, `speech-model`, that makes no sound): four notices, namely the speech model is missing, the model is downloading (the downloading notice shows the progress sentence; its bar fills when the total is known and is endless when it is not and while the archive is checked), the download is done or has failed, and the tile could not be shown. Each tap is one immutable `PendingIntent.getActivity` to the launcher with a request code of its own. The words are Kotlin constants, in plain words for the user; with notifications switched off nothing shows.
- Host package `dev.breaker.dictation.host` (the Android classes that join the wiring to the platform; checked by text gates):
  - `AppThreads.kt` - `MainLooperPost` (runs a block on the main looper, always queued, never inline; it also implements `DelayedPost` for the notice clear and the keyboard re-evaluation; `registerOnMain` also registers the display-change listener on the main looper) and `SerialBackground` (blocks one at a time, in order, on one named daemon thread; a block that throws is dropped and the next still runs). It is the only file in the app that names a handler, a looper, an executor or a thread.
  - `DisplayChangeAndroid` - the `DisplayPort` over the platform's display manager; it registers one display-change listener with the main-looper handler, so the callback, the snapshot and the watch run on the main thread; the snapshot is the default display's rotation plus the physical size of its current mode, with no window manager and no refresh rate or mode id.
  - `OverlayTilePort` - the `TilePort` over the overlay module's `FloatingTile`; built on the first show; maps the show result to `TileShow`. Its `level` passes the value on to `setLevel` on the tile with no state check; the RECORDING check is in `LevelFeed`. Its `onDisplayChanged()` forwards a display change to the tile and does nothing until the tile has been shown once.
  - `TakenClipboardAndroid` - the `TakenClipboard` over the phone's primary clip, labelled with the app's name; main thread only.
  - `TileHost` - builds the tile coordinator and the model downloader over the one model store. `onArmedChanged(armed)` (any thread) starts or stops the gesture and shows or hides the tile, `onLauncherVisible()` shows the tile again while the switch is on, `requestDownload()` is the download entry point, `setDownloadListener(listener)` sets the in-app download listener (the activity sets it while visible and clears it), and `openLauncher(route)` makes it the `Opener` of the tile. Its `onArmedChanged` also starts or stops the display-change listener on the main looper, beside the shake gesture. Its `init` hands `onTakeEnded` and `onMicTaken` from the composition root to the coordinator through the main post. The taken line reaches the notification through `setNotificationLine`: `DictationNotification.withText` for a line, and the plain `build` when the line is cleared. The coordinator's clipboard seam is `appTakenClipboard(context)`, and its history is the app's history store. Its `init` sets the root's `levelSink` to its one `CompositeLevelSink` (a `CopyOnWriteArrayList`, safe to add to and remove from while `publish` runs on the audio thread) and adds a `LevelFeed` over its own tile and main post, so one level source feeds the tile and the Home mic; `addHomeLevelSink` / `removeHomeLevelSink` add and remove the Home sink (the activity adds it in `onCreate` and removes it in `onDestroy`). It also owns `takeWorker`, the one serial take worker the tile and Home share.
- Wiring package `dev.breaker.dictation.wiring`:
  - `DictationComponent` - builds the capture, the two core use cases and the runner from their ports; `close()` drops the dictation, switches the service off and is idempotent; `bindTo(scope)` closes it when the scope ends.
  - `DictationRunner` - drives one dictation at a time: `begin()` (`BeginResult`, whose `Taken` answer means another app or a call holds the microphone), `finish()` (`FinishResult`), `send()`, `cancel()`, `onCaptureEnded()`, `onServiceEnded()`, `resetAfterTaken()` (a taken take back to idle, with no second audio stop), `disarm()`. It stops capture, never the service, except `disarm()`. `RunnerSentences` holds its plain sentences.
  - `LazyHistoryStore` - a `HistoryStore` that builds the real one on first use; a supplier that throws is not remembered.
  - `UnavailableSttEngine` (now the server engine slot only), `UnavailableMicSource` - the honest-failure slots: one for the server engine (not built), and one for the microphone, which is the composition root's default when none is handed in (the app hands in the real one) (with `SERVER_UNAVAILABLE_DETAIL`, `MIC_UNAVAILABLE_MESSAGE`); each answers with a failure, never a success. The on-device engine is the real `OnDeviceSttEngine`, and the recognizer behind it is the real one, held by the swap point `RECOGNIZER_FACTORY`.
  - `FirstRunDoneStore` (with `FirstRunGate`) - the first-run done marker: a file named `first-run-done` in the app's files folder whose presence is the whole fact; its text is never read. `markDone()` writes it through a temporary file renamed in one step and answers false when the write fails; `isDone()` never throws. `FirstRunGate.decide(done, modelReady)` answers FIRST_RUN (no marker and no model), MARK_DONE_QUIETLY (no marker and a ready model: a phone from before the first run is marked quietly) or NORMAL (the marker is there).
  - `UuidIdSource` - the `IdSource` over random UUIDs.
  - `DisplayWatch` - plain Kotlin over the `DisplayPort`: it takes a baseline at start, watches only the default display, and runs `onChanged` only when the snapshot differs; a refresh rate switch is the same snapshot, so it runs nothing.
  - `LevelTap` - the `AudioSource` that `DictationComponent` puts around the microphone capture. Each frame goes to the listener first and unchanged, and only then is its level handed to the `LevelSink`, inside a catch of `Exception`, so an exception on the level path never reaches the capture; an `Error` still propagates. Each `start()` makes a fresh `LevelMeter`.
  - `LevelMeter` - the level of one take: the RMS level of the whole window of frames since the last update (every sample of those frames counts, not only the last frame), with an update each time 1067 samples have been counted (about 15 a second at the default 320-sample frame). The remainder is carried, and a frame gives at most one update. The meter owns one `NoiseFloor`, so a new meter starts a new floor, and the bar shows the window level above that floor. A higher level is shown at the next update; the shown level falls by at most one twelfth of the bar per update. It has no thread, no clock and no lock.
  - `LevelMap` - the one map from a level in dBFS onto 0 to 1: `levelOf` gives the level of a dBFS value above a zero point (default -60 dBFS) up to -6 dBFS, clamped at both ends, and no information (null) gives 0. The helpers `sumSquaresOf` (the sum of squares of a frame; null when a sample is NaN or infinite) and `dbfsOf` (10 log10 of a sum of squares over a count; null when there is no energy) build the window level, so a silent window gives 0 and a frame with a non-finite sample adds nothing to the sums.
  - `NoiseFloor` - the per-take noise floor of the bar, one object owned by each `LevelMeter` (so each take starts a fresh floor). The floor is seeded by the lower median of the window levels while the take has counted fewer than 8000 samples (counted through the end of the update). After the seed it falls at most 30 dB per second (2.0006 dB per update of 1067 samples) and rises at most 1 dB per second (0.0667 dB per update), and it never goes below -60 dBFS. The zero point of the bar is the floor plus 8 dB, capped at -18 dBFS. Digital silence (no information) never seeds the floor and does not move it. The constants are in `FloorTuning`, in the same file. It has no thread, no clock and no lock.
  - `LevelFeed` - the `LevelSink` that carries a level from the audio dispatch thread to the tile on the main thread, through `MainPost`. The posted block forwards the level only while the take's session state is `RECORDING` at that moment (`TRANSCRIBING` is excluded), so the state is read on main.
  - `TilePorts.kt` - the ports of the tile: `TileShow`, `TilePort`, `MainPost`, `Background`, `TakePort`, `ModelReady`, `ModelNotice`, `Opener`, and `ROUTE_MODEL_VALUE` ("model", equal to `NotificationRoute.ROUTE_MODEL`). `TakePort` also has `resetAfterTaken`, which `TakePortAdapter` passes to the runner.
  - `tileStateFor` - the one function that decides which state the tile shows; the busy face of a taken take (`micBusy`) comes after the off switch and before the sending, failed and sent states.
  - `TileCoordinator` - what each tap does and which state the tile shows: `onArmedChanged`, `onBegin`, `onShake` (a shake shows a closed or hidden tile and begins nothing), `onCancel`, `onSend`, `onTap`, `onTakeEnded` (wired through `MainPost` when the mic ends by itself) and `onTakeMicTaken` (wired through `MainPost` by the tile host, for a take cut by the microphone); `onBegin` also needs the tile to be showing, so a failed or refused show means no begin. It is called on the main thread only; the take runs through `Background` and the answers come back through `MainPost`. `TakePortAdapter` presents the runner as a `TakePort`.
  - `TakeYield.kt` (`TakeYieldController`, internal): the taken branch of the coordinator, with the busy face flag, the lead line at the cut, the finish, reset and save on the background, and the copy and the settle line on the main thread (invariants 19 to 24). The settle always runs, even when the save to history fails.
  - `TakenClipboard.kt` - the one-method seam a taken take copies through (`copy(text)`), main thread only; the Android copy is `TakenClipboardAndroid` in the host package, built by `appTakenClipboard(context)`.
  - `TakenSentences.kt` - the pinned lines of a taken take (`LEAD`, `SAVED_AND_COPIED`, `TAKEN_NOTHING_HEARD`, `NOT_CONVERTED`, `COPIED_NOT_SAVED` and `STILL_TAKEN`), Kotlin constants, not string resources.
  - `NoopPorts.kt` - `GesturePort` with the placeholder `NoGesture`; the plain `appGesture()` in `Swaps.kt` keeps returning it.
  - `LaunchRule.kt` - `isIconLaunch(action, categories, route)`: true only for the start the launcher icon makes (the main action, the launcher category and no route); plain Kotlin that takes strings and names no Android type.
  - Home mic (F45, ADR-026): the overlay module's `ScreenMic` is the Home mic; ui places it in its slot (`HomeHostView.attachMicSlot`) and the app composes it: `HomeScreenMic.kt` (wraps `ScreenMic.create`; `setState`, `setLevel`, `setTheme`), `HomeTakeWiring.createScreenMic` (tap and begin go to `onTap`, X to `HomeTakeAdapter.onCancel`, the check to `onSend`) and `host/ActivityHelpers.kt` (`createHomeMic` passes ui's `HomeControl.TAP_TO_TALK`, `CANCEL` and `DONE`; `addHomeLevelSink` builds the `HomeLevelFeed`). `HomeTakeAdapter`: X cancels (nothing saved, the mic released); the check or a second tap finishes, saves to History and copies to the clipboard, never a send or a commit; begin, cancel and finish run on the shared take worker, never the main thread (`HomeTakeAdapterThreadTest`, `SharedTakeWorkerGateTest`, `HomeMicWiringGateTest`).
  - `IconLaunchOnce.kt` - the once-per-instance rule for the icon launch: plain Kotlin with no Android type; it decides between the switch-on and the start-up arm, and the activity saves its done flag.
  - `ArmedSwitch` (with `SwitchOn`) - the one on and off switch over the controller: `isOn`, `switchOn`, `switchOff`, `armAtStart` and `onStateChanged` (the observer body). `OffStore` and `FileOffStore` - the user's switch-off kept as the presence of one file, written to a temporary file and renamed.
  - `ModelSupport.kt` - `ModelSentences`, `StoreModelReady`, `ModelInstallPort` (with `InstallerPort` and `modelInstallPortFor`, the adapter over the installer of the speech module), `InstallOutcome` (`Installed`, `NoSpace`, `Refused`), `ModelDownloadNotice`, `DownloadOutcome` and `ModelDownloader`, whose `requestDownload` is the one download entry point. `ModelSentences` holds the downloading sentence template (`DOWNLOADING_TEMPLATE`) with the `downloadingFor(sizeMb)` function that fills in the converted size, and the `mibToMb(sizeMb)` conversion from mebibytes to the decimal megabytes Android shows. `ModelSentences` also holds `CHECKING` and the progress sentences (`progressFor`, `progressUnknownFor`), with `doneMb` and `totalMb` for the megabyte counts; `ModelDownloadNotice` has a `progress` method, and `ModelInstallPort` has a callback form of `install` whose default ignores the reports.
  - `Swaps.kt` - the swap points, in the table below (none of them names an Android type).
  - `AndroidSwaps.kt` - the android half of the swap points: the swaps that need an Android type live here, namely `appTextCommitter(context)` (the accessibility commit), `appMicSource(audioManager)` (the real microphone) and `appGesture(context)` with its `ShakeGesture` mapping (the real shake of the phone, read from the accelerometer), and `appTakenClipboard(context)` (the clipboard a taken take copies to, main thread). They are kept out of `Swaps.kt` so that file stays plain.
  - `KeyboardHideHold` (internal) - keeps a keyboard-gone hide that comes during a take and lets it through once, when the take leaves flight, if the last keyboard reading still says the keyboard is gone; a keyboard show, a user close or a switch-off clears it. Plain Kotlin.
  - `KeyboardReevaluation` (internal) - holds the newest keyboard reading that arrives inside the 250 ms debounce window and re-evaluates it once, when the window ends, through the `DelayedPost` seam; at most one post is pending.
  - `KeyboardTileDecision.kt` - the public sealed type `KeyboardDecision` (`Show`, `Hide`, `NoOp`) and the internal pure function `decision` over four presence flags and two time stamps, with `DEBOUNCE_MS` (250).
  - `KeyboardTileSession` (internal) - the keyboard session's flags (active, raised, closed during the session) and the last reading pair; `onKeyboardReading` returns the decision the coordinator acts on and never shows or hides the tile.
  - `KeyboardTileWiring` (internal) - collects the readings of the commit module's holder on `Dispatchers.IO`, skips the reading that was current when it started, and posts each other reading to the main thread through `MainPost`.
  - `TilePortCalls` (internal) - the coordinator's port calls that may throw (session state, model check, background submit); each answers a fixed value (`IDLE`, `false`, `false`) when its port throws.

After a send the tile shows SENT until the next begin, cancel, tap or switch-off. A send whose text was committed, or only reached the clipboard, also shows SENT; a failed commit shows FAILED with its sentence. A tap on a tile that shows SENT starts a take; a shake does not (see invariant 18). The text itself is never given to the tile, and there are two timers: the notice clear that lines 147-150 describe, and the keyboard tile's one pending re-evaluation at the end of its 250 ms debounce window. The app does not push SENT_LOCAL: no producer exists, because the server path is not built, and a server failure is surfaced, not retried on the phone.

The debug build only (`android/app/src/debug/`) holds the Home mic probe: an exported broadcast receiver for the action `dev.breaker.debug.MIC` (extras `state`, `redraw` and `shape`) and a not-exported start provider that starts the probe with the process. The release build holds none of it: its manifest and its sources name no probe element, and the probe is removed before release. The receiver reaches the Home mic only through the overlay module's public `ScreenMicProbe` interface, pushes a state, triggers a redraw or selects the halo shape, logs under the tag `BreakerMicProbe`, and never starts a take. The release manifest names neither; the `ScreenMicProbe` interface, the log sink and the touch-down and route log lines of the overlay's `ScreenMicProbeKit`, and the `HomeHostView` probe log lines are diagnostic and are removed with the probe before release. `ScreenMicProbeKit` itself is not: its host click decision (`hostAction`, `hostClick`, `dispatch`) is the production accessibility click path of the Home mic.

## Owns
app entry, DI container (composition root), Gradle build, and the file-backed credential-reference holder (a `Keystore` impl that holds the reference, not the secret), the foreground microphone service and its notification, the https-only network configuration, the manifest, the honest-failure slots for the parts that are not merged, the tile coordination (what a tap does and which state the tile shows), the user's close of the tile (kept in memory only, tested by `TileCoordinatorShownTest` and the wiring rule `OVERLAY_TILE_PORT_PASSES_EVERY_HELD_CALLBACK_TO_CREATE` in `OverlayTilePortGateTest.kt`), the user's switch-off file, the entry point of the speech model download, the rule that opening the app from its launcher icon switches dictation on, the run-time dependency on the speech engine release file with the check of its pin, the start-up purge, which now runs the clock-jump guard (`PurgeGuard` through `runGuardedStartPurge`) instead of a bare `purgeExpired()`, reading automatic-time-on through `AndroidAutomaticTimeOn` and keeping its baseline in `PurgeBookkeepingStore`, and the host package that holds the app's Android threads and adapters.

## Swap Points
Where a part that is not built is swapped for the real one. Each is one declaration in `wiring/Swaps.kt`, or in `wiring/AndroidSwaps.kt` when it needs an Android type (the text committer, the android half of the swap point); the composition root and the tile host read them, and nothing else names a placeholder. `SwapsTest` pins what each answers today.

| Swap point | Today | What the swap needs besides a new body |
|---|---|---|
| `RECOGNIZER_FACTORY` | `SherpaOnnxRecognizerFactory()`, the real recognizer, with the thread count the module chooses; building it loads no native code, the engine library is opened when a model is first loaded | nothing for the real one. What stays swappable: the thread count (an argument, none today) and a different factory. The engine library is a run-time dependency of the app, checked by `verifySherpaAar` before the app's build tasks |
| `appTextCommitter(context)` in `wiring/AndroidSwaps.kt` (the android half of the swap point) | `CommitServices.create(context)`, the accessibility commit of the commit module, made once per process from the application context | nothing for the real one, but the user must switch the service on in the system settings; `ACCESSIBILITY_SERVICE_COMPONENT` is the exact string for its service (package, a slash, the full class name) and is checked against the commit module's manifest by `AppCommitGateTest`. A committer that copies to the clipboard counts as sent and says nothing, so it must have its own sentence |

## Test Requirement
Every test added or touched for this module must be proven to fail loudly:
break the protected behavior on purpose, confirm the test fails and says why,
then restore the code. A test that only ever passes proves nothing. This
applies to every tier and invariant listed above, not only the ones that seem
fragile.

## How This Module Is Built
One engineer owns this module and delivers it as one pull request, working on
one module at a time. The owner does not write the module's code. The owner:
- splits the work into sub-modules and has contributors write each one, code and
  tests;
- coordinates and orchestrates those contributors, checks every piece of their
  work, and sends back anything that is wrong until it is right;
- convenes a small panel of contributors to advise on design, risks and tests
  before and during the build;
- hands the finished, checked module directly to the maintainer as a single pull
  request.
The owner's own work is orchestration, checking and correction, not writing
code.

## Known Gotchas
- `SettingsLauncherActivity.kt` is 300 lines. `AppLayoutGateTest` holds every Kotlin file of this module to 300 lines, so a change that adds code to the activity moves code out of it first.
- Phase 1 deliverable - DI wiring must be the ONLY place modules are composed.
- **Emulator gate before any APK.** JVM tests and source-text gates cannot see Android layout or lifecycle. A change that touches layout, Views, redraws or the activity lifecycle is run on the Android 16 emulator (API 36) before an APK goes out: upgrade over the previous APK (with the first-run marker) and a fresh install, at window heights 1500, 1800, 2000, 2400 px and 1440x3120 at density 560, plus background/foreground, rotation and dark mode: full Home every time, no crash. The emulator cannot record audio, so recording states are pushed into the mic through a debug-source-set hook (that hook is not in main yet). Three launch defects were found only there and are fixed in main: the redraw re-adding the one mic view (ui `attachMicSlot` detaches it first), the unset `settingsView` on first run (`SettingsViewSetBeforeFirstRunTest`), and a blank Home on a tall phone (ui `TouchGapView` measures itself, `TouchGapMeasureGateTest`).
- **OPEN defects from the APK 8 phone test** (cause not found unless stated; required behaviour): (A, blocker) while recording, the X and check on the Home mic are drawn but not tappable and the take sticks; required: X cancels, check finishes, a second tap on the mic finishes. The project owner saw history and the model gone after an update; not reproduced: the gate reviewer's emulator test: an in-place update from APK 6 to APK 8 keeps history and model; APKs 1-5 were each signed with a different key, so 5 to 6 could not install over (INSTALL_FAILED_UPDATE_INCOMPATIBLE) and needed an uninstall; APKs 6, 7 and 8 share one key (cert SHA-256 a8225bc3). It is a top-level function of the wiring package, not a member of `TileCoordinator`; its readings are the keyboard window and the focused text field. The debounce is 250 ms: a reading inside the window is held, and the newest held reading is re-evaluated once when the window ends, through one pending post. `TileCoordinator.onKeyboardReading` acts on the result, `KeyboardTileSession` keeps the session flags, and `KeyboardHideHold` holds a keyboard-gone hide that comes during a take. **PLANNED, no code:** `PhraseSendHandler` (spoken Send, ADR-004), the one owner of phrase detector start/stop, the audio tee and the one-Send-per-take gate.   start-up purge once on an app-lifetime coroutine scope on the I/O dispatcher

  `PurgeGuard` clock-jump decision reads `PurgeBookkeepingStore.lastPurgeAt`

  GO (automatic time on, no baseline yet, or within 30 days of the last purge); a

  then runs as normal. A failure is passed to a callback that logs it (`Log.w`);
  it is not retried and does not crash the app. Purge scheduling beyond app start

- A shake of the phone goes to `TileCoordinator.onShake`, which never begins a take. With the switch off, or a take running, it does nothing. With the tile on screen and not closed by the user it does nothing. - The sensor is started as soon as the service is armed, whether or not the tile can be shown, so a shake with no tile on screen reaches `TileCoordinator.onShake`, which brings the tile back if it can be shown and begins nothing.
- A start the sensor refuses (for example, a phone with no accelerometer) leaves nothing listening. It is tried again at the next switch-on.
- The sensor is registered only while the service is on: it is registered when the service goes on and released when it goes off or the service ends.
- If the process dies, Android drops its sensor listeners; the app has no code for that case. **NOT VERIFIED on a device.**
- Shake events are delivered on the main looper, because the module registers its listener with no Handler. **NOT VERIFIED on a device.**
- The shake is read at the game rate, 50 samples per second, which needs no permission. **NOT VERIFIED on a device**: the thresholds of the detector were not tuned on hardware.

- A level posted by one take can reach the tile after the next take has entered `RECORDING`: the posts run in order on main, the check reads only the state, and there is no take token. This is a stated limit. One update covers 1067 samples at 16 kHz, about 67 ms; that is the scale of the window and does not bound the delay.
- The two input routes use different capture sources: a call-style Bluetooth route records with VOICE_COMMUNICATION (platform voice processing, which usually suppresses steady noise) and every other route records with MIC (raw). On the built-in route the old fixed-range bar rested near the middle of the bar (about 50 to 55 percent) in background noise for that reason. The bar now follows a per-take noise floor on every route, so steady noise reads 0 on both; normal speech (about minus 20 dBFS) still reads clearly. Quiet speech (about minus 30 dBFS) on a very quiet route reads lower than before.
