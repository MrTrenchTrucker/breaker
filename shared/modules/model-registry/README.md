# model-registry — README

The one list of speech-recognition models for the phone and, as planned (ADR-016), the server; no server code reads it today: sizes (in MiB and in bytes), download URLs that name a release asset, our own SHA-256 pin and byte size for each model, and each model's license. Every download is checked against that pin, the SHA-256 and the byte size (built, unit-tested, not tried on a phone, in the downloader); upstream's checksum.txt is advisory, compared with our pins when the registry is authored and never fetched on install. Each entry also records the upstream revision the model came from (an entry that is not tamper verified may leave it out), its exact
license, and the upstream file name it downloads as (checked against the checksum
the upstream publishes, for an archive it lists, at authoring time only), and a CI check refuses any entry with a missing or malformed field. The phone names models through constants generated from this list (ADR-016).

Status: `models.yaml` holds five speech entries: `small` and `tiny` (streaming Zipformer, English), `parakeet` (an offline model; its offline recogniser is built in the speech module but its native binding is compiled against the library by the project's CI build, and it has not been tried on a phone) and `base` and `medium` (Whisper, English; their kind is `offline` in the data and the engine still refuses them). Each entry carries its own byte size and release-asset id, and `small` (Good, 1 of 3) and `parakeet` (Better, 2 of 3) are the offered entries, with the label and rating the screens show (built, unit-tested, not tried on a phone). Each speech entry also records what the engine needs (its model type, the four file names, the extraction limits and the language), exactly one offered entry is the default, and `parakeet` carries its attribution notice; the generator refuses an offered entry whose (kind, model type) pair is not in `tools/model_types.py` (built, unit-tested, not tried on a phone: run as Python tests; the generated Kotlin compiles in the project's CI build, and app code reads these fields). The generator `tools/gen_model_registry.py`, the committed generated Kotlin and the tests are in the tree. The hosted copies (F30, D25) are not built: every entry has `hosted: false`.

Decided in ADR-050: a `parakeet` entry (Parakeet TDT 0.6B v3, CC BY 4.0) with the label "Better" and a rating of 2 of 3 truck emoji, and `small` labelled "Good", 1 of 3. They are built, unit-tested, not tried on a phone, as registry data; the screens that show them, the About entry and the NOTICE text are built too, with the same status.

Full module card, including how to run its tests: `AGENTS.md` in this folder.
